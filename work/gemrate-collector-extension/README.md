# GemRate POP 日次受領

## 0.1.3：同日追加の設定同期

公開の小さな版付き設定だけを15分ごとに確認する。版はセット/年/言語/対象数/基準日/優先度のSHA-256で、提供元の新観測ではない。設定版・対象コード/数・最終同期日時を小窓へ表示し、次の実ページ受領証にも保存する。日本時間の翌日を待たず新対象を巡回へ追加する。既存の確認済み日・保留・試行予算・受領意図は初期化しない。既存コードの年/セット変更は仕様保留とする。

同じ専用フォルダの更新後、Chrome拡張管理で再読み込みする。権限の変更や再インストールは不要。「対象設定を再同期」は提供元取得/CSVクリックを行わず、実行中は出力の完了を待つ。「1セットだけ通常CSV出力を試験」は設定同期に不要で、押し直さない。新規取得はPC/Chrome起動中、受領後の保存/検証/公開は既存の非AI経路で別実行する。

初期状態は停止。確認済みの日本語・PSAセットだけを通常公開ページで確認し、元基準日が進んだ場合だけ通常の Export to CSV を1回押す。既存セットの日次枠と、確認済み新セットの1日1枠を分ける。CSVの反復処理は新観測にしない。

## 実行範囲と権限

- PCとChromeの起動中だけ動く。PC電源OFF時の新CSV取得を解決するものではない。クラウドの既存受領・公開処理は別。
- GemRate公開ページと、このサイトの公開設定を読むホスト権限、alarms / storage / scripting / downloads を使用する。
- Chromeのdownloads権限自体はダウンロード履歴全体を参照できる。コードが引き取るのは、自分が開始した確認済みセットのCSV（URL・referrer・開始時刻・ジョブID一致）だけ。
- APIキー・契約・課金・新規アカウント・認証回避は使わない。403等のアクセス画面や仕様矛盾は保留し、自動解除しない。
- 安全制限を緩めない。出力開始後に受領不明となった場合は再クリックしない。ダウンロード保存先を確認できなければ保留。

## 保存と受領

専用の Downloads/GemRate-Auto/pending/ジョブID に CSV と receipt.json を保存する。ページの元基準日と確認日時を別記録する。同日未更新の確認では証跡だけを出し、CSVを再取得しない。

既存の毎時PC受領処理が、原本・ハッシュ・バックアップ・仕様を検証し、既存の照合・履歴・最小公開チェックポイントへ接続する。原本と圧縮バックアップの一致を確認した専用フォルダ内の重複コピーだけを整理し、一般のDownloadsや失敗ファイルには触れない。

## 検証状態

単体・実CSV再照合と、拡張導入後の実取得・複数周期の日次運転は別。パッケージ生成だけでは導入・ON/OFFの実状態は分からない。2026-11-04に利用者から導入済み・ON・エラーなしの申告を受領。実取得は専用受領証跡で別確認する。

操作場所は Chrome 右上の拡張メニュー（🧩）→「GemRate POP 日次受領」。小窓の「非AIの日次確認を有効にする」が日次運転のON/OFF。「1セットだけ通常CSV出力を試験」は別操作で、通常の有効化に押す必要はない。

popup の単発試験は同じ基準日でも一度CSVを出して受領経路を確認するが、新基準日・新POP観測には数えない。保留解除機能は設けない。

## 0.1.2 の受領保留対策

CSV受領保留と、認証/アクセス/仕様保留を分離。前者でも提供元の1日1回確認は続ける。現行版の単発試験で正確な出力URLのファイルを専用先へ受領できた後に限り、他セットも保留発生日より新しい元基準日分だけ1回の復旧対象にする。同じ元基準日の再クリックはしない。受領成功したセットの技術保留だけ履歴へ移し、アクセス/仕様保留は従来どおり停止する。単発試験は版ごと1回・古い試験意図と保留は保持する。受領成功と、PC取込み/原票照合/参考公開は別に計測する。

新しいCSV試験では、通常ボタンを1回押した際にDOMへ追加されたCSVアンカーのblob URLを一意に記録し、そのURL・同一セット・開始日時に一致するダウンロードだけ専用フォルダへ受け取る。referrerが空でもこの正確な対応が必要。別ページ・別blob・複数アンカー・不明な出力方式は保留し、再クリックしない。受領側も同じ対応と全行数/PSA合計/元基準日を独立検証する。新権限やURL安全機能の変更はない。
