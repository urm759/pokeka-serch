# ポケカ仕入れ判断サイト

この `github-site` フォルダだけで、GitHub Pages の表示とデータ自動更新が動きます。

## GitHub にアップロードするもの

- アップロードするのは、この `github-site` フォルダの中身だけです
- `index.html` が GitHub リポジトリのルートに見える配置にします
- 親フォルダ側の `work`、`.github`、`outputs` を別々にアップロードする必要はありません
- `.github/workflows/refresh-all-site-data.yml` で毎日04:30と17:00（日本時間）に全データを一括更新します
- 個別の相場更新とカードラッシュ更新は、Actions画面から手動実行できます

## 仕組み

- `index.html` が本体
- `app.js` でフィルタと利益率計算
- `data/pokemon-cards-meta.json` にデータ取得日を保持
- `data/pokemon-cards.json` に `toreca-souba.com` のポケモンカード全件を集約
- 画面上で `PSA鑑定プラン`、`直近30日下限`、`直近7日下限`、`PSA10時利益率 下限`、`現在仕入値×中央予測` の期待利益、`仕入れ上限×供給ストレス予測` の安全側利益、`PSA10上下限`、`平均美品価格帯`、`検索` を変更可能
- URL パラメータ `?fee=13000&tx=30&tx7=0&roi=40&psaMin=0&psaMax=200000&priceMin=&priceMax=&sort=roi-desc&q=` にも対応
- 平均美品価格は、みんトレ・カードラッシュ・晴れる屋2・遊々亭・トレカキャンプの状態A価格から算出した外れ値除外中央値です。特定サイトを固定優先せず、近い価格が過半数を占める場合は多数側を採用します。更新14日超は重みを下げ、45日超、状態違い、紐付け疑いは除外します
- 複数店舗の価格が一致して単独の外れ値を安全に除外できた場合は「外れ値除外済み」として判定を続けます。価格が複数グループに割れる、カード違いが疑われる、信頼できる状態AまたはPSA10価格が0件の場合だけ「要確認」としてGOを停止します
- PSA公式未取得や状態A価格1件は「データ不足」として、判定信頼度を下げて3〜5%の追加リスクを反映し、GO／価格次第の判定は続けます
- 「手動確認を除外」で要確認だけを省けます。「データ分類で絞る」では、手動確認・データ不足・外れ値除外済み・注意表示なしを個別に表示できます
- 「現実的な仕入れ上限 相場比下限」は、美品の最終仕入れ上限 ÷ 平均美品価格 × 100で判定します。70を指定すると、相場の70%未満でなければ買えないカードを除外できます
- `PSA10時利益率` は `現在PSA10手取り－平均美品価格－PSA鑑定費` を `平均美品価格＋PSA鑑定費` で割った値です。`期待利益率` はPSA10率とPSA9以下の出口を含み、「現在仕入値×91日後中央予測」で計算する別指標です
- 安全側利益は「仕入れ上限×供給ストレス予測」で計算します。利益率下限0%はPSA10率、PSA9以下、販売手数料、鑑定費、追加費用を含む期待値が0円以上という意味で、PSA9など全ての鑑定結果で赤字にならない保証ではありません
- 美品の動きは、みんトレ取引件数とカードラッシュで確認できた在庫減少数を7日・30日で分けて表示

## 変更しやすい箇所

- PSA鑑定費を変えたい: 画面上部の入力欄
- 取引数の条件を変えたい: `直近30日 下限`
- 直近7日の動きも絞りたい: `直近7日 下限`
- PSA10 20万円以下に絞りたい: `PSA10 上限`
- PSA10 の最低価格も見たい: `PSA10 下限`
- 美品の値段レンジを絞りたい: `美品 価格帯`
- データ取得日を変えたい: `data/pokemon-cards-meta.json`
- 画像やカードを増やしたい: `data/pokemon-cards.json`
- 並び順を変えたい: `並び順` セレクト

## 自動更新

`Refresh All Site Data` が毎日2回、日本時間の午前4時30分と午後5時に開始します。
みんなのトレカ相場の新カード・価格・取引件数を取得したあと、スニダン直リンク、カードラッシュの商品・状態A価格・在庫を順番に更新します。
午前4時30分開始分は、通常は午前6時までの完了を見込んだ設定です。ただしGitHub Actions側の混雑や取得元サイトの応答状況によって遅れることがあります。

サイト上部の「データ更新状況」には、取得元ごとの予定時刻、開始・終了、最終成功、所要時間、成否、取得件数、更新件数、失敗数、次回予定、取得成功だがデータ元に変更なし／取得処理失敗の区別を表示します。直近の処理履歴は取得元ごとに折りたたんで確認できます。過去に計測していない項目は推測せず「未記録」とし、次回の更新から実測値を保存します。遊々亭とトレカキャンプは独立処理のため、一方が失敗しても他の取得元は更新を続けます。Actionsの手動実行時は `source` から失敗した取得元だけを選んで再実行できます。同じワークフローの同時実行は `concurrency` で防止しています。

「ショップ状態Aの連携状況」では、カードラッシュ、晴れる屋2、遊々亭、トレカキャンプ、PSA公式を同じ項目で監査し、総取得、自動紐付け、手動紐付け、未紐付け、曖昧候補、紐付け率を表示します。「取得商品内の紐付け成功率」「全サイトカードに対するカバー率」「照合対象内のカバー率」は分母が異なるため、別々に表示します。共通正規化ではセット番号、カード番号、名称、レアリティ、収録弾、特殊仕様を照合し、国内ショップはカード名不一致も自動候補から除外します。`data/linkage-review.json` に再確認候補、`work/manual-card-aliases.json` に確定エイリアスを保存し、確定後は次回更新で再判定しません。

更新の最後に `work/build_evaluation_model.js` が同じPSA10価格帯の取引・買取掲載・利益率の候補分布を再集計します。候補は `data/evaluation-model-candidate.json`、採否と履歴は `data/evaluation-governance.json` へ分離します。30日と出口のウォークフォワード検証、基準モデルとの差、変更幅上限、手動承認を満たすまで本番モデルを変更しません。画面の「銘柄品質」は売りやすさ35%、価格安定25%、供給リスク耐性15%、将来価格25%です。

`work/build_market_analysis.js` は価格・取引・出品・店舗別在庫を最大91日だけ差分保存し、画面用の軽量な下値安定サマリーを生成します。履歴不足時は点数を作らず「蓄積中」にします。異なるサイトの取引数と在庫数は合算せず、在庫消化日数は同一店舗の現在在庫 ÷ 1日平均在庫減少数で店舗ごとに計算し、その中央値だけを表示します。

`Refresh Pokemon Site Data` と `Refresh Cardrush Stock` は個別確認用の手動実行として残しています。通常の定期更新は `Refresh All Site Data` だけで完結します。

### 手動で今すぐ一斉更新する

スマホまたはPCで GitHub のリポジトリを開き、`Actions` → `Refresh All Site Data` → `Run workflow` → 緑色の `Run workflow` の順に押します。処理と公開はGitHub側で行うため、自分のPCを起動したままにする必要はありません。

みんトレ、カードラッシュ、Web買取表、トレカクラブ、PSA Japan料金、評価モデルはこの操作で更新できます。PSA公式PopulationはPC側のログイン済みPSA専用Chromeから自動取得します。認証期限が切れた時だけ、専用Chromeで再ログインが必要です。

## お気に入り仕入れ候補

各カードの「仕入れ候補に追加」からお気に入り登録できます。同じカードを複数枚買う場合だけ数量を増やし、実際の仕入れ単価も保存できます。お気に入り一覧は `保存した仕入れ単価×数量` の合計を使用可能資金と比較します。登録内容はブラウザごとの保存ですが、CSV保存とCSV読込で別のスマホ・PCへ移せます。
お気に入り全体についてPSA10相場が一律10%、20%、30%、40%、50%下落した場合の期待利益、赤字カード数、赤字総額、必要予備資金を表示します。最大1銘柄比率、銘柄分散、予備資金、仕入れ時期の分散は期待値とは別のリスク管理として扱います。
メモ用コピーでは、カード名、PSA10価格、美品と多少の傷ありの仕入れ上限をスマホで確認しやすい形式にまとめます。

## 下値安定・店舗需要

「下値安定」は既存のGO・価格次第・期待利益・仕入れ上限とは独立した指標です。価格方向、下値状態、需給状態を分け、14日・30日・90日のA品価格とPSA10価格、変動幅、新安値、支持帯、取引、出品、店舗別在庫、PSA10供給増、発売後日数、店舗間価格一致、市場PSA10指数比を評価します。判定開始基準は14日が4記録・10日幅、30日が8記録・21日幅、90日が16記録・60日幅です。不足中の方向は「暫定上昇・暫定横ばい・暫定下降」、増加数は0ではなく「蓄積中」とします。同日の複数更新は終値用の最新値と瞬間安値用の最安値を1日1記録へ統合します。

履歴不足中は「暫定観測帯」と表示します。確定支持帯は、異なる3日以上で同価格帯に接触し、その後に下抜けせず反発または維持した場合だけ成立します。終値ベースと瞬間安値ベースを別々に保存し、終値が確定支持帯を明確に割った場合は「下値割れ」へ変更して次の低い候補帯を再計算します。現在価格を中心に機械的な幅を付けただけの帯は、確定支持帯として扱いません。

カード上部では「下値安定」「店舗需要」「将来価格」「売りやすさ」「期待利益」を別々に表示します。銘柄品質と今回の仕入れ判断は互換性のため従来計算を維持し、新指標を混ぜてGO判定を変えません。

PSA10買取率は `店舗買取÷PSA10市場価格`、相場差率は `買取率−1`、フリマ手取り比は `店舗買取÷手数料差引後手取り` です。すべて小数点3桁で表示します。相場より高い買取価格も有効な売却候補として保持し、最高買取先へ反映します。ただし1店舗だけの高額買取を市場全体の需要が強い根拠にはせず、店舗集計の標準値はカードごとの買取率中央値を主指標にします。

店舗需要は買取率30点、店舗数20点、掲載継続率20点、買取価格推移15点、PSA10売買流動性15点です。掲載継続率は掲載観測日数÷取得成功観測日数で計算します。観測3日以下は59点、4～7日は69点、8～13日は84点を上限とし、14日以上だけ100点まで許可します。「強い」は絶対条件を満たしたうえで同価格帯の原則上位30%だけに限定します。

`work/build_market_backtest.js` は、判定日の価格、仕入れ価格、PSA10率、PSA9以下価格、鑑定費、売却手数料、弱気・中央・強気予測、各評価点を変更不可の日次スナップショットとして圧縮保存します。同日の再実行では最初に保存した値を上書きしません。保存期間は標準91日の資金ロック期間に35日を加えた日数以上です。

7日後・30日後は「再評価期待利益」、91日後または設定された資金ロック期間後は「想定出口利益」として検証します。予測誤差率、方向一致率、予測レンジ内的中率、支持帯割れ率、買取率維持率、GO利益プラス率を、現在価格維持の基準モデルと比較し、価格帯・店舗需要点・下値安定点ごとにも集計します。実際の鑑定結果と売却価格をブラウザへ入力した場合だけ「実現利益」を表示します。バックテストは既存の仕入れ計算には影響しません。

GOの期待値計算は変更せず、表示上の信頼度だけ「GO・確認済み」「暫定GO」「GO・高リスク」に分けます。必要履歴と店舗需要が揃うと確認済み、下値安定が蓄積中なら暫定、下降・下値割れ・店舗需要が弱い場合は高リスクです。それぞれ検索条件で絞り込めます。

店舗集計には取得成功率、相場乖離率、カード誤紐付け疑い率、紐付け隔離件数を表示します。相場乖離率は店舗の買取が強い・弱いことを示す参考値で、価格を無効にはしません。自動隔離はカード番号・セット・レアリティの照合信頼度が低い場合、または保存済み紐付けと最新の厳格照合が衝突した場合だけに限定します。

## 状態別の仕入れ上限

各カードの上部に「美品なら」「多少の傷ありなら」の2つの仕入れ上限を表示します。美品はPSA公式取得率、公式未取得時は選択中の70%または50%基準を使用します。多少の傷ありは美品のPSA10取得率を45%下げ、PSA9以下の回収額も安全側へ補正して再計算します。

PSA9は、直近の正しい実成約、30日中央値、60日中央値、90日中央値、年代・価格帯・レアリティ別PSA10比率、平均美品価格75%の順で採用します。現在の公開データにはPSA9成約個票がほぼ含まれないため、多くは最後のフォールバックであり、画面に「実成約未取得・推定値」と表示します。PSA10も個別成約が取得できた場合は外れ値除外後の中央値・直近加重中央値・最安最高・最終成約日・採用元を表示し、未取得時はみんトレのスニダン集約値と明記します。期待利益は `PSA10率×PSA10手取り＋（1－PSA10率）×PSA9以下手取り－仕入れ価格－鑑定費` で統一し、売却手数料と追加費用を両方の出口から控除します。

上限は3種類です。通常上限は91日後の中央予測で目標利益を残す価格、供給ストレス時赤字回避上限は供給過多まで追加反映した価格でも期待利益0円以上となる価格、超低リスク上限は同じ供給ストレス価格でも目標利益を残す価格です。理論上限は通常 `min（通常上限、供給ストレス時赤字回避上限、資金上限）`、低リスク候補プリセットだけは超低リスク上限を使用します。

実店舗で使う運用上限は理論上限と分離しています。1万円未満は500円、3万円未満は1,000円、10万円未満は2,500円、それ以上は5,000円単位で切り下げます。履歴がない初回は固定価格や架空の前回値を使わず、理論最終上限を価格帯別単位で切り下げた値をそのまま暫定運用上限にします。危険方向の引き下げは即時、小幅変動は3%のデッドバンド内で据え置き、値上げは異なる更新日の理論上限が3回続いてから反映します。履歴は同じブラウザへ日次で保存し、3日未満は暫定、7日以上で確定度高とします。詳細には初回区分、前回上限と日付、理論上限、平滑化方式、運用上限、制限理由を表示し、上部には全カードで最も集中している運用上限と件数を表示します。

カード詳細の利益比較は、購入価格を「現在仕入値」「運用上限」、PSA10売却価格を「現在相場」「中央予測」「供給ストレス」に分けた6通りです。同じ売却価格なら、運用上限時の利益は現在仕入値時の利益から仕入値差だけ増減します。

「相場基準では仕入れ圏」は外れ値除外中央値が運用上限以下という意味です。「購入先確認済み／今すぐ仕入れ」は、取得2日以内、在庫あり、価格監査済みの店舗販売価格が運用上限以下の場合だけ表示します。成約中央値、在庫切れ、古い価格、購入価格未取得、価格対立だけでは今すぐ仕入れにしません。「薄商い・高粗利」は暫定GOまたは価格次第だけを対象とし、見送りを除外します。

損益耐性として、PSA10のみの損益分岐価格、PSA10率とPSA9以下価格を含む期待値損益分岐価格、目標利益維持価格、現在相場からの下落余力、供給ストレス時の期待利益、PSA9だった場合の損益を表示します。これらは「現在の平均美品価格で仕入れた場合」と明記します。一律20%下落を安全基準には使用しません。

### 供給パイプラインと供給ストレス上限

PSA10増加数を同期間のPSA10取引数で割った「供給圧力比」と、その逆数である「供給吸収率」を7日・30日で計算します。30日履歴を優先し、不足時は充足した7日履歴だけを暫定使用します。期間不足、増加0枚、取引0件は0倍とせず「蓄積中」です。発売後18か月以内、状態A取引、PSA10取得率、鑑定期待利益、ショップ在庫、PSA10出品、店舗買取も別々に評価し、状態A需要が将来のPSA供給予備軍になる可能性を加味します。

「供給ストレス価格」は既存の弱気予測を起点に、古い価格・単独異常値・誤紐付け疑いを除いた2店舗以上のPSA10買取中央値、確定支持帯、市場相対強度、供給圧力比を反映します。下落補正率は `market-analysis.js` の `SUPPLY_STRESS_CALIBRATION` に分離してあり、バックテスト結果から調整できます。

通常の弱気予測と供給ストレス価格は別指標です。通常の弱気予測は既存の価格予測、供給ストレス価格はそこへ供給過多を追加反映した価格です。供給ストレス価格を供給ストレス時赤字回避上限・超低リスク上限に使い、供給リスクは出口価格へ一度だけ反映するため二重控除しません。カード一覧は実際に使う最終上限だけを大きく表示し、詳細では現在価格で買った場合と各上限で買えた場合の期待利益を分けて確認できます。

## PSA提出判断

`PSA提出判断の設定` で、仕入れ用総資金、ロック中資金、資金ロック日数、最低期待利益、最低期待利益率、最低年換算資金効率、1枚の最大資金占有率、同時提出枚数、返却時の鑑定費予備資金、売却手数料、送料等を変更できます。
入力値はURLへ自動反映されるため、そのURLをブックマークすると同じ条件で再度開けます。
さらに、`PSA10時利益率 下限` と `現実的な仕入れ上限 相場比下限` は同じ端末・同じブラウザ内へ自動保存します。URLにこれらの条件がある場合はURLを優先するため、共有リンクやブックマークの条件は崩れません。期待利益率・期待利益額はURLの `filterExpRoi`・`filterExpProfit` に保存できます。

使用可能資金は `総資金－ロック中資金－鑑定費予備資金` です。個別カードは常に1枚として判定し、同時提出予定枚数を仕入れ価格へ掛けません。同時提出予定枚数は返却時に必要な鑑定費予備資金の確認に使います。実際に選ぶ複数カードの合計仕入れ額はお気に入り一覧で比較し、同じカードを複数買う場合だけその数量を掛けます。

PSA10率は公式値、PSA9は実価格を優先し、未取得時だけ画面設定と平均美品75%を使います。予測下落、供給増、回転、データ不足は中央・弱気予測価格の作成に反映し、期待利益式の後から固定20%や重複する安全率を差し引きません。

## 価格データ監査

- みんトレ状態Aは成約相場、各ショップ状態Aは販売価格として別種別で保持し、販売価格を成約件数には加算しません
- 美品価格の詳細には取得元、価格種別、状態、更新日、採用・除外理由、採用範囲、価格乖離、信頼度、現在購入できる最安の店舗価格を表示します
- カード番号・セット・レアリティの保存済み照合が低信頼または競合する店舗価格は計算から除外します。言語・仕様情報を取得元が提供しない場合は、取得済みのカード識別子以上の断定はしません
- PSA10は現在、みんトレが提供するスニダン集約価格、7日・30日取引数、掲載下限、最終取引日を使用します。個別成約明細と成約価格範囲は保存されていないため、他鑑定会社、海外版、取消取引、送料をサイト側で再監査できません。この制約を詳細画面へ表示し、取得元集約値を独自の中央値と偽って表示しません
- 現在価格は外れ値除外した基準価格、現在購入できる店舗価格は採用済み販売価格の最安値です。仕入れ判断のGOは現在の基準価格が運用上限以下の場合だけです

## かんたん絞り込み

- `おまかせ総合` は今すぐ仕入れ、低リスク候補、高回転候補の和集合で、国内出口・価格信頼度・仕入れ上限があるカードだけを表示します
- `今すぐ仕入れ` は現在価格が運用上限以下のカードです
- `低リスク候補` と `高回転候補` は価格待ちを含みます。低リスク候補は現在価格で買えるカードと上限待ちを切り替えられます
- `薄商い・高粗利` は価格帯別のPSA10成約基準を使い、30日成約0件、出口なし、誤紐付け・外れ値・データ不足を除外します
- カードには `今すぐ`、`低リスク`、`高回転`、`価格待ち` の該当理由タグを表示します

最終結論は5種類です。「GO」は現在価格で全条件を満たす、「価格次第」は値下がりだけでGOになる、「要確認」は手動で価格・カード同一性を確認しないと判断できない、「資金不足」は採算条件を満たすが1枚の価格が現在の資金上限を超える、「見送り」は価格を下げても銘柄品質またはリスク条件を満たしません。データ不足だけでは要確認にせず、安全補正後の通常判定を表示します。銘柄品質60点未満は見送り理由へ点数と一緒に表示します。

## 91日後の価格推計

PSA10の将来価格は期間を91日後と明示し、弱気・中央・強気の3価格を表示します。「データ充足度」は取引件数、買取店舗、PSA公式取得率・増加履歴、ショップ紐付けの取得状況を表し、価格上昇を保証する確度ではありません。買取価格は最新日の有効価格の中央値を予測へ使い、市場PSA10価格から大きく離れた単独店舗値は除外します。

## GitHub Pages に置く方法

1. この `github-site` フォルダを開く
2. 中にあるファイルとフォルダをすべて GitHub リポジトリのルートへアップロードする
3. GitHub Pages の公開元を `Deploy from a branch`、ブランチを `main`、フォルダを `/(root)` に設定する
4. Actions の `Refresh Pokemon Site Data` と `Refresh Cardrush Stock` を有効にする
