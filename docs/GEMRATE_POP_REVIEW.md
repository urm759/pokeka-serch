# GemRate POP取得の確認（2026-10-23）

## 到達点

- 日本語版イーブイヒーローズのV・SR・SA 8種について、公開ページ上のセット・番号・名称を掲載済みIDへ一意に照合。通常SR・VMAX・外国語版は混在させない。
- PSAフィルターのPSA10・PSA総枚数・更新日、個別の週次推移を閲覧できた。これは公開ページの手動確認であり、API取得・新規POP補完・公開利用の実証ではない。
- セット一覧と個別推移で値が一致しない例が1枚ある。更新日だけで前後を接続せず、集計範囲・自動サイン等の仕様・取得時点を確認するまで既存PSA履歴へ混ぜない。
- 確認原票はGit外の非公開保管。公開JSONへPOP値・履歴を移植せず、保存済みの公式原票・チェックポイントは維持。

## 正規経路と停止理由

- [公式API](https://docs.gemrate.com/introduction)は全要求に `x-api-key` が必要。これはAPIの要件であり、公開ページ閲覧にもキーが必要という意味ではない。利用者は契約・キーなし、契約/登録/問い合わせ送信は保留。API呼出0。
- [Partner API](https://www.gemrate.com/partner)は日次更新とPOP/履歴の提供を案内しているが、料金は相談方式で公開価格を確認できない。無料・有料額を推測しない。
- [公開利用規約](https://www.gemrate.com/terms)は知的財産の帰属を記載。確認した本文に公開ページの自動取得・少数確認を一律禁止する明文は見つからない。一方、継続収集・保存・公開再利用の一般的な許諾も確認できない。「明文禁止なし」を再公開許諾とみなさず、非商用なら無条件に許可とも判断しない。

## 公開ページとAPIを分けた実測

| 操作 | 今回確認できた範囲 | 未確認・停止範囲 |
| --- | --- | --- |
| 公開ページの通常閲覧 | ログイン/APIキーなしでPSA指定の日本語セットと個別推移を閲覧、既存8枚へ照合 | 閲覧できたことを継続収集や再掲載の許諾へ拡大しない |
| 少数の試験取得 | ブラウザ表示8行を非公開の検証資料へ保持。セット一覧に通常のCSV出力ボタンあり | CSV受け取りはブラウザ応答停止で未確認。同操作の連続再試行なし |
| 通常HTTPでの取得 | robots.txtは404。個別履歴HTMLの通常GETを1回試したところ403 | 403後は再試行・別経路による回避なし。robotsの不存在は許諾の根拠ではない |
| 継続収集・継続保存 | 公開ページ/APIで別途判断が必要 | 利用範囲と安定した正規取得が未確立。定期キューへ未接続 |
| 公開サイト・Gitへの再掲載 | 調査結果の説明のみ | POP原票・値の自動転載なし。保存済み確認資料はGit外で保持 |
| 公式API | キー・権限・利用枠の要件を公式資料で確認 | キーなしのAPI試行、契約・課金・問い合わせ送信なし |

公開ページをキー不足の理由で一律停止する扱いは訂正する。現状の実停止要因は、通常HTTPの403、CSV取得未確認、継続利用/再公開条件未確認、下記の値の不一致であり、それぞれ別件。現時点で本人操作は求めず、国内補完を継続する。

## 不一致1枚の再確認

- グレイシアV・077・2021日本語イーブイヒーローズ・Full Art・Base・PSAの指定はセット一覧と個別リンクで一致。通常SR/VMAX/他社Gems合算を誤って比較したものではない。
- セット側の更新日10月22日と、個別側の更新日10月23日が異なる。個別ページには週次推移の表記がある。FAQ上のUpdatedは取り込み/処理日なので、最終週の表示日を正確な公式実取得日時へ付け替えない。
- 週次区間の採用点、ページ別更新、集計差のどれが原因かは未確定。CSVを確認できず、通常HTTPも403だったため、特定原因へ断定せず保留を維持。今回の差を実際のPOP減少/増加としない。
- 数値と日時の対照は非公開の検証資料へ保持。旧PSA原票は上書きせず、同一仕様でも取得元の切替前後を連続した供給増減にしない。

## 利用可能になった場合の検証要件

- [カードPOP](https://docs.gemrate.com/api-reference/cards/get-population-for-a-card)：`GET /v1/cards/{gemrate_id}/population`。`by_grader.psa.grades.psa_10` と `by_grader.psa.total` を使用し、他社を含む `gem_total` /全社合計を使わない。PSAのspec ID、セットURL、日本語・番号・加工を照合する。
- 分母のグレード範囲・qualifier/authentic・サイン版の分離を確認し、PSA公式のTOTALと同一定義であると先に決めない。`data_last_updated` と `last_population_change` も区別する。
- [POP履歴](https://docs.gemrate.com/api-reference/cards/get-population-history-for-a-card)は別の履歴権限が必要。[エラー/上限](https://docs.gemrate.com/errors-and-limits)の401/403/429・利用枠・待機時間を遵守する。
- [FAQ](https://www.gemrate.com/faq)の `Updated` は取り込み/処理日であり、公式の実取得日時と同じとは限らない。日付しかなければ日精度のまま保持。週次記録を日次200点へ補完しない。
- 将来採用する場合も「GemRate集計」とデータ基準日を表示。取得元変更・再分類の差を市場のPOP純増へ数えず、公式履歴とは根拠別に保持する。

海外価格関連の凍結、PSA直接取得の独立した許諾待ち、既存の採算式・購入GO・検索条件は変更しない。
